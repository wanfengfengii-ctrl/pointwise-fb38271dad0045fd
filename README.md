# 事件时间双路全外区间关联（Streaming Full-Outer Interval Join）

纯 Python 标准库实现。两个乱序到达的记录流（`L` / `R`）按事件时间做
全外关联：同 `key` 且 `|tL - tR| <= W` 的跨侧记录两两配对（多对多，
每对恰好一次）；始终没有配对的记录在水位关闭其时间窗口后输出一次
未匹配元组。

## 文件

| 文件 | 作用 |
| --- | --- |
| `joiner.py` | 交付实现：`Join(W)`，`push / advance / finish` 均返回迭代器 |
| `reference.py` | 两个**独立**参照：暴力嵌套循环 `ReferenceJoin`；`bisect`+`heapq` 流式 oracle `OracleJoin` |
| `verify.py` | 16 组核验：规格样例、边界、惰性语义、treap 结构、300+60 组随机差分、复杂度探针 |
| `cli.py` | 标注演示 `demo` 与长流资源实测 `bench` |
| `.pointwise-runtime.json` | 运行清单（version 1 / kind cli） |

## 快速开始

```bash
python3 -I verify.py          # 全量核验（无第三方依赖）
python3 -I cli.py demo        # 带注释的端到端演示
python3 -I cli.py bench --records 200000 --window 4
```

## 编程接口

```python
from joiner import Join

j = Join(W)                       # W 为非负整数
for out in j.push("L", "a", "k", 10, payload): ...   # (left_id, right_id)
for out in j.advance("R", 22): ...
for out in j.finish(): ...
```

* 输出元组形状恒为 `(left_id, right_id)`：配对时两侧均为字符串；
  未匹配时另一侧为 `None`。输出顺序不做承诺。
* 三个方法都返回**迭代器**，结果按需产生，不在内部累积配对。
  调用方契约：耗尽当前迭代器后再发起下一次操作（未启动的迭代器
  不产生任何副作用，见 `test_unconsumed_iterator_has_no_side_effects`）。
* 输入约束按题设强制校验：`side ∈ {L,R}`；`id/key` 为字符串且各侧 ID
  全程唯一；`time` 为整数且严格大于本侧当前水位；水位只能单调不减地
  推进到整数或 `float("inf")`；初值为负无穷；`finish()` 后禁止 `push`。

## 操作顺序与释放规则

每次操作严格按题设顺序执行：

1. **先关联**：`push` 时只在对侧、同 key 的**活动**记录上做时间区间
   `[t-W, t+W]` 查询，命中即配对；
2. **再释放**：用本侧水位 `wm` 释放对侧满足 `t + W <= wm` 的活动记录
   ——未配对者输出一次未匹配元组，已配对者静默删除；
3. `finish()` 等价于双侧水位同时升至 `+inf`，排空全部状态。

已配对记录**绝不提前释放**：`paired` 标记只抑制未匹配输出，记录本身
仍留在索引中，直到水位关闭其窗口才被删除（这保证它不会被后续记录
重复配对，也保证状态可被水位正常回收）。

## 正确性论证

**配对完备性。** 设跨侧记录 `x`（先到，时刻 `tx`）与 `y`（后到，时刻
`ty`）同 key 且 `|tx-ty| <= W`。`y` 到达时其时刻严格大于本侧水位
`wm`（输入合法性），而 `x` 的释放条件是对侧水位 `>= tx + W`。由
`ty <= tx + W` 得 `wm < ty <= tx + W`，故 `x` 此刻仍在活动索引中，
`y` 的区间查询必然命中 `x`。

**配对唯一性。** 每对只在“后到记录 push”时由单侧区间扫描产生一次；
记录被水位释放后即从 treap 物理删除、永不回流，因此不存在重算或
重复配对，也从不扫描整 key 重算历史配对。

**未匹配恰好一次。** 每条记录在整个生命周期内只被堆弹出/删除一次；
弹出时当且仅当 `paired` 为假才输出未匹配元组。

**顺序与 finish。** 关联先于释放是代码固定顺序；`finish()` 将双侧
水位置为 `+inf` 后依次排空两个释放堆，与“水位升至正无穷”语义一致。

## 索引说明与复杂度

活动记录数记为 `A`，某 key 下活动记录数 `A_key <= A`，一次 push 的
配对数记为 `K`。

### 两套互补索引（均按侧分开维护）

1. **每 key 一棵 treap（随机化 BST）**，键为 `(time, id)`。
   * 优先级来自内部 `random.Random` 的 64 位随机数，与键无关，树高
     期望 `O(log A_key)`（10 万节点期望高度约 20 余层，远低于递归
     上限；区间遍历本身用显式栈实现，无递归深度问题）。
   * 区间查询 `[t-W, t+W]` 用键界 `(lo, "")` / `(hi, 最大哨兵)` 做
     **剪枝中序遍历**：整棵落在窗口外的子树直接跳过，访问节点数为
     `O(log(A+2) + K)`，辅助栈 `O(log A)`，逐节点 `yield`、不缓存
     结果列表。`verify.py` 的 `test_range_query_complexity` 实测
     2k→32k（16 倍）规模下访问量只增长常数倍。
   * 插入、删除期望 `O(log A_key)`；空树立即回收 key 字典项。
2. **每侧一个全局最小堆**，堆项为 `(time + W, time, id, key)`。
   * 释放是全局时间序问题（与 key 无关）：堆顶即最老的到期记录，
     每条记录整个生命周期只入堆、出堆各一次。

为什么需要两套索引：treap 回答“同 key 下哪些记录落在时间窗内”
（关联），堆回答“哪些记录已被对侧水位关闭”（释放）；二者通过同一份
`_Rec` 对象协同，删除时 treap 与堆各移除一次。

### 复杂度汇总

| 操作 | 期望复杂度 |
| --- | --- |
| `push` 关联区间扫描 | `O(log(A+2) + K)` |
| `push` 入索引（treap 插入 + 堆插入） | `O(log A)` |
| 单条记录的释放（堆弹出 + treap 删除） | `O(log A)`，全流每条记录仅一次，总量 `O(N log N)` 摊销 |
| `advance` | 仅水位变化时触发释放，摊销同上；无到期记录时 `O(1)` |
| `finish` | 线性排空剩余状态 |
| 状态空间 | **`O(A)`**：每条活动记录一个 `_Rec`、一个 treap 节点、一个堆项 |

`bench` 实测（每侧 20 万记录、持续推进水位）：活动峰值约 5k，与流总
长度无关，只取决于水位推进形成的时间视界；40 万记录约 4 秒，结束
状态为 0。重配对场景（单 key、2000×2000 条同刻记录、3.6 万级配对）
配对随迭代器逐条流出，活动状态保持 `O(A)`，不缓存配对。

## 核验策略

* `ReferenceJoin.expected()` 缓存全量输入后用双重嵌套循环重算期望
  结果集，是小规模随机场景的最终真值；
* `OracleJoin` 用与交付实现**完全不同的数据结构**（`bisect` 排序列表
  + `heapq`）独立实现同一套操作顺序，支撑长流逐批比对；
* `test_differential`（300 组，5 万+输出）做 treap 实现 vs 暴力真值；
  `test_three_way_differential`（60 组）再做 treap vs bisect oracle
  的**逐操作批次**比对，并与暴力真值三方对齐；
* 另有水位截止时刻不变量、窗口边界 `|Δt|=W`、`W=0`、多对多不重复、
  key 隔离、非法输入拒绝、惰性迭代、treap 增删查对照有序表等检查。
